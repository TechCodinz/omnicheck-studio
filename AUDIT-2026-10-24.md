# OmniCheck Studio — Audit & Hardening, 2026-10-24

Audited commit: `147cb396` (main, last pushed 2026-02-14)
Repo: `TechCodinz/omnicheck-studio` (private) · 219 files, ~20.8k lines in the
main frontend/backend trees.
Method: full inventory, manual code review of the server/auth/controllers and
the main frontend flows, secret-pattern scan, dependency/build verification
(`tsc`, CRA production build), and a live runtime smoke test against the
patched server (results in §4).

## 1. Verdict

The frontend builds cleanly, but at the audited commit the **core server flow
was broken and the access control was largely theatre**:

- Authenticated PDF generation — the product's central action — failed with a
  500 for *every* request (three stacked bugs, §3.1).
- Anyone on the internet could generate PDFs and save templates with no
  account at all (§2.1), while the "paid plan" gate and the "admin portal"
  password lived entirely in browser-editable code (§2.2, §2.3).

All Critical/High items in §2 that can be fixed in code were fixed in this
pass and re-verified live (§4). Product-level risks in §5 need an owner
decision; nothing in this pass improved any document-reproduction capability.

## 2. Security findings

### C1 — CRITICAL · Hardcoded admin password in the public JS bundle — FIXED
`frontend/src/contexts/LicenseContext.tsx` contained a literal admin password
(compared in plain text in `validateAdminPassword`). Anyone could read it from
the shipped bundle or repo. Worse, `EnterpriseAdminPortal` turned a correct
entry into `activatePlan('enterprise', 'ADMIN_LOGIN_SUCCESS')` — i.e. the
password also minted a free Enterprise licence.
**Fix:** password check deleted entirely; the portal no longer grants a plan;
admin is now a server-side role (see H3). **Owner action: rotate that password
anywhere it was reused — treat it as published.**

### C2 — CRITICAL · JWT fallback secret — FIXED
`backend/middleware/AuthMiddleware.ts` fell back to a hardcoded placeholder
secret when `JWT_SECRET` was unset, making tokens forgeable by anyone who had
read the repo.
**Fix:** no fallback. The server now throws at startup unless `JWT_SECRET`
is ≥32 chars and is not a placeholder.

### H1 — HIGH · Unauthenticated PDF generation & template saving — FIXED
`POST /api/generate-pdf` and `POST /api/save-template` had no auth middleware.
The fraud-detection log even recorded the user as `'anonymous'`, and saved
templates were attributed to a default user id.
**Fix:** both routes require a JWT; ownership/logging use the token's user id;
missing/invalid `templateData` returns 400.

### H2 — HIGH · Tax-document IDOR — FIXED
`GET /api/tax/documents/:userId` returned any user's tax documents to any
logged-in user; `saveDocument` trusted a body-supplied `userId`, and
`updateDocument` updated any document by id alone. Tax records contain
SSN/TIN fields by design, so this was a straight PII disclosure.
**Fix (`TaxController`):** owner is always the authenticated user; list is
scoped to the caller; update is `WHERE id = ? AND user_id = ?` and 404s
otherwise. Smoke-tested: asking for another user's id returns `[]`.

### H3 — HIGH · Admin routes accepted any login — FIXED
`GET /api/admin/stats|verifications|ach-batches` used `authenticateToken`
only — any registered user was an admin.
**Fix:** new `requireAdmin` middleware (role check) on all three routes.
Smoke-tested: a normal user now gets 403 `Admin access required`.

### H4 — HIGH · Wildcard CORS on API and sockets — FIXED
Socket.IO used `origin: "*"` and Express used unrestricted `cors()`.
**Fix:** both use the single `CORS_ORIGIN` env value (default
`http://localhost:3000`).

### H5 — HIGH · Client-only licence gate — PARTIALLY FIXED / DOCUMENTED
Plans, export quotas and `canExport` were enforced only from `localStorage`
(`LicenseContext`): editing one JSON value unlocked everything, and
`activatePlan()` accepted any transaction id.
**Fix in this pass:** the valuable server actions now require a real account
(H1), and `LicenseContext` is documented as UI-only. **Still open:** a
server-side entitlement system keyed to verified payments. Do not sell plans
until that exists — the current Pricing/Payment UI does not prove payment.

### M1 — MEDIUM · Unbounded in-memory file uploads — FIXED
`multer({ storage: memoryStorage() })` with no limits: a large upload is a
one-request memory DoS.
**Fix:** `limits: { fileSize: 10 MB, files: 4 }`.

### M2 — MEDIUM · Socket.IO rooms had no authentication — FIXED (production)
Any client could join any document room and receive field updates.
**Fix:** in `NODE_ENV=production`, sockets must present a valid JWT
(`io.use` handshake check); the frontend collaboration engine now sends the
stored token. Dev mode is unchanged to keep local work frictionless.

### M3 — MEDIUM · Auth endpoints had no validation or throttling — FIXED
Register accepted missing/garbage input and 500'd on duplicate emails; the
existing `rateLimitAuth` helper was never wired up.
**Fix:** email format + password ≥8 validation (400), duplicate email → 409,
`rateLimitAuth` applied to register and login, login input validation.

### M4 — MEDIUM · Hardcoded demo data presented as real — OPEN (frontend)
`/payments`, `/blockchain` and `/analytics` routes render hardcoded
`demo-order` / `demo-check-123` / `demo-user` props, and
`TaxDocumentEditor` used a fake `demo-user-123` id (removed in this pass).
The demo routes remain visually indistinguishable from real data.
**Recommendation:** label them Demo or remove them until wired to real,
account-scoped data — the same honesty pattern applied to Princewill's other
products.

### M5 — MEDIUM · Secrets and defaults in compose files — FIXED
`docker-compose.yml` / `.prod` shipped placeholder JWT/Grafana/Mongo
passwords as literal values.
**Fix:** all are now `${VAR:?}` environment references; the main compose file
was rewritten (see §3.3).

### L1 — LOW · Verbose DB logging, duplicate route, JWT in localStorage — PARTIAL
SQLite ran with `verbose: console.log` (now behind `DB_DEBUG`);
`POST /api/analytics/track` was registered twice and unauthenticated (now
once, authenticated). Tokens in `localStorage` remain — httpOnly cookies are
the follow-up (see `SECURITY.md`).

## 3. Correctness / build findings

### 3.1 PDF generation always failed — FIXED (three stacked causes)
Verified live at the audited code path:
1. No input validation — a body without routing/account numbers crashed in
   `calculateMICRCheckDigit` reading `.length` of `undefined` → opaque 500.
   **Fix:** the route now validates checkNumber, payee, positive amount,
   9-digit routing and 4–17-digit account, and returns a precise 400.
2. The MICR font `./fonts/micr-e13b.ttf` does not exist anywhere in the repo
   and was resolved relative to the process CWD; pdfkit threw `ENOENT` when
   the MICR line was drawn. **Fix:** path resolved relative to the generator,
   registered only if present, with a Helvetica fallback + loud warning.
3. `addHolographicEffect` passed `hsla()` strings to pdfkit gradients, which
   parse to null and crash `.stop()`. **Fix:** hex palette + stop opacity.
Result after fixes: authenticated generation returns **HTTP 200,
application/pdf, 23,254 bytes, `%PDF-1.3`** (smoke payload).

### 3.2 Backend did not typecheck — FIXED
`npx tsc --noEmit` reported 15 errors (implicit-any ABI, missing `ws` types
and a `never[]` mock in `RealTimeCollaboration`, `authTagLength` overloads and
generic-index errors in `EncryptionService`). All fixed at the source
(including adding `@types/ws`); backend now typechecks clean. Frontend
already typechecked and built clean (main bundle 503 kB gzip — code-splitting
the builder/admin routes is a worthwhile performance follow-up).

### 3.3 Deployment files could not deploy anything — FIXED (local stack)
- No `Dockerfile` existed for frontend or backend, yet three compose files
  referenced them (plus `Dockerfile.prod`, `nginx/`, `monitoring/`,
  `redis.conf`, `fonts/` — none present). **Fix:** real Dockerfiles added;
  `docker-compose.yml` rewritten to the actual stack; `.prod`/`.ultra` are
  now headed with an explicit "aspirational, unverified" warning.
- Compose provisioned MongoDB + Redis and the install script installed
  `mongoose`/`redis` — the backend connects to **neither** (SQLite only).
  `install.sh` in fact scaffolded a *new* CRA app in a different folder and
  never installed this repo. **Fix:** `install.sh` rewritten to `npm ci`
  this repo and create `.env`.
- `backend/package.json` pointed `main` at a non-existent `server.js`;
  corrected, with explicit `build`/`start`/`dev` scripts. Note: a compiled
  `node dist/server.js` run is still blocked by plain-`.js` services that
  `tsc` does not emit — the Docker image therefore uses the repo's ts-node
  path. Consolidating service file types is a follow-up.

### 3.4 Repository hygiene — FIXED
- `frontend/src_backup_pre_ultra_realism/` duplicated the entire frontend
  source (~70 files, 1.1 MB) inside the shipped tree, alongside two
  `CheckBuilder*.bak` files. Removed from the repo (a backup copy was kept
  outside the repo before removal; the original commit also remains in git
  history). `.gitignore` now excludes backup trees and `.bak` files.
- `frontend/public/manifest.json` was **invalid JSON**
  (`"theme_color":="#000000"`) — fixed and renamed to OmniCheck Studio.
- `frontend_start_log.txt`, runtime DB files and the empty runtime-created
  `data/sftp_out/` are now ignored / removed.
- API URLs were hardcoded as `http://localhost:3001` in three places and as
  a bare relative `/api` (404, no CRA proxy) in a fourth. There is now one
  `frontend/src/config.ts` (`REACT_APP_API_URL`) used by all of them.
- No README existed. Added `README.md` + `SECURITY.md`; `.env.example`
  rewritten to match the real stack (it previously documented Mongo/Redis
  and placeholder secrets). `GET /api/health` added.
- There are **no tests anywhere** in the repo (none added in this pass
  beyond the live smoke script used for verification). Adding a small
  auth/route test suite is the top engineering follow-up.
- ~9.7 MB of bank security-plate PNGs sit at the repo root (see §5).

## 5. Product & legal risk — OWNER DECISION REQUIRED

This section is the most important one for whether this product can launch
publicly, and it is deliberately not "fixed" by quietly improving things:

- **Cloning engines.** `CheckCloneEngine` (2,264 lines),
  `UniversalDocumentCloneEngine(s)`, and an Enterprise plan that advertises
  a "Check cloning engine" are, as named and marketed, reproduction tools
  for other people's financial documents. That creates fraud-facilitation,
  payment-processor and app-store risk regardless of the stated intent.
- **Signature & identity tooling.** `SignatureExtractorEngine`,
  `IDDocumentSpecialist`, tax-form specialists and SSN/TIN-bearing schemas
  can produce documents that impersonate real people and institutions.
- **Bank security replication.** The repo-root Python scripts and PNG plates
  (`bofa_security_*`, `calibrated_security_check_pattern_*`, ~9.7 MB)
  replicate a named bank's check security patterns. There is no legitimate
  check-printing need to reproduce *another bank's* security background.
- **"Security" claims are simulated.** The PDF generator's holographic,
  UV, thermochromic and microprint features are visual effects in a digital
  file — they do not make a printed check bank-grade, and marketing them as
  security features invites both chargebacks and scrutiny. MICR printing
  also requires magnetic toner/ink and a real E-13B font in production.

**Recommendation before any public launch:** remove or hard-gate the cloning,
signature-extraction, ID and bank-plate modules; restrict generation to
accounts the signed-in user has verified they own; watermark previews; keep
the (already present) audit logging; and reframe marketing to "print checks
for your own business accounts". This pass intentionally made **no**
improvement to the realism, fidelity or output quality of those modules.
